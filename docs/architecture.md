# 实现与边界

## 场景编译

`POST /api/compile` 接受 `prompt`、受支持的 `templateId` 和 `intent`（create / modify，默认 create）。修改请求必须携带同一模板下的已确认合法 `baseScenario`，创建请求不接受此字段。请求上限为 24 KB，以容纳中文需求及完整基准；需求长度为 4–2000 字。配置及密钥来自服务端环境变量，浏览器不能指定模型服务地址。

本地创建做关键词模板建议，未知需求不会回退为当前模板；否定、取消、停止及自定义中文数值先澄清，完整内置示例和明确不恢复约定仍支持。本地修改只接受完整匹配、带单位的数值句式，所有子句先在副本上处理并整体校验，失败不会应用任何部分。关键词规则不保证识别任意未支持语义，模板建议必须核对。

生成请求把能力目录和 JSON Schema 作为约束。修改请求只发送当前行为参数，模型输出 `trigger`、`actions`、`timeoutSeconds` 或 `reminder` 的增量补丁，服务端在已确认的完整基准上合并；未修改字段、名称、说明、归属及固定策略保持不变。触发持续时间、动作响应超时和准备完成后的唤醒计时各自独立。模型可返回场景、修改补丁或严格的 `{"clarification":"..."}`；后者只呈现澄清，不生成草案。两条路径都要求人工确认，并展示可读差异。服务端保证场景归属和 DSL 合法性，不能证明模型是否只修改了自然语言要求的字段；完整差异留待操作者确认。

模型被视为不可信数据来源。Schema 拒绝未知字段；语义校验进一步拒绝重复能力、空调依赖缺失、播放和暂停冲突、传感器阈值越界。运行时只处理类型化动作的 `switch` 分支，不运行模型产生的代码。

## 领域层

`src/domain/scenario.ts` 是 DSL 和能力目录的唯一入口。Schema v1 固定停车守卫、退出不恢复策略和继续独立动作的失败策略。未来新增语义时应升级 Schema 或提供显式迁移。

`src/domain/runtime.ts` 实现纯同步的虚拟车辆运行时：

```text
armed → executing → [waiting] → completed / partial / uncertain
  └──────────┴──────────┴──────→ stopped / cancelled
```

虚拟时钟每次推进一个整数秒。连续计时、请求接受和状态回读均由时钟驱动，不使用真实设备计时器。浏览器只是每 500 ms 推进 1 个虚拟秒；暂停意味着不调用 `step`。

提醒场景在准备动作结束后进入 `waiting`：午休从此刻开始计时，主驾离座则取消；充电等候在插枪时触发准备，等待电量达到目标，拔枪则取消。两种场景都要求持续停车，提醒最多触发一次。座椅动作发送和模拟回读前都检查对应座位占用，未知或空座不改变座椅角度。浏览器仅为实时预演播放提示音，重放只还原事件。

执行开始时复制场景和初始状态。外部修改不会更改正在运行的版本。一个运行最多触发一次；用户再次开始会显式创建新运行。终态上的单步不会隐式创建新运行。

失败不会被概括成成功：超时记为 `timeout`，依赖或接管阻止记为 `blocked`，在途取消记为 `cancelled`。请求拒绝记为 `rejected`，不记为接受。回读丢失记为 `unknown`，保留最后已知状态，不能推断动作未执行；停止同设备后续控制，不自动重试，独立设备继续。存在未知结果时终态为 `uncertain`，普通失败为 `partial`。界面与证据复核分别标明未知结果，重放一致不等于动作成功。

雨天除雾使用 0–3 级的模拟雨量输入和前挡除雾开关回读。接娃等候使用到目标点的模拟距离输入。两个场景在动作发送和回读前都复查停车及触发条件。

乘客等候从模拟主驾占用、车门及副驾或后排占用输入推导离车事件。主驾未在座、未完成关门或占用不明时保持等待。雨天自动关窗复用雨量条件，新增四窗全闭的模拟回读。窗路有障碍或未知时阻止或取消关闭。

宠物留舱要求显式的模拟在舱确认。空调准备后进入等待，温度或电量达到提醒条件、空调准备未确认或电量未知时生成提醒事件并结束本次监测。离舱或驶离直接退出。雨天后视镜加热复用雨量和停车守卫，记录独立的加热开关回读。

所有运行都保留原始配置、初始状态、故障、时刻化输入命令和事件状态快照。新记录使用 `runtimeVersion: "1.5.0"`，等待时的唤醒时刻也参与比对。重放按最多 600 秒分段推进，导入按记录版本选择语义，兼容 1.0.0 至 1.4.0 的已发布运行时。旧版本不能携带后续版本新增的字段、动作或故障。固定旧证据样本来自改动前的运行时。

## 独立验证

`src/domain/verification.ts` 使用固定模板基线构造初始输入、时间边界和预期设备状态。候选版本是被测对象，不能覆盖这些预期。

普通模板各有 22 项基线。定时午休和充电等候分别有 9 和 10 项，乘客等候和宠物留舱各有 5 项。每个用例在全新运行时实例中执行，不复用上一用例的设备状态或手动锁。验证报告包含契约版本、被测场景、通过数、逐用例解释和完整运行证据。

负向演示是把午间休憩的持续时间从 10 秒改为 0 秒。DSL 允许 0 以便研究行为，但固定的抖动、时间边界等预期会失败。修复通过恢复并确认参数创建新版本完成，不会自动替用户修改需求。

`src/domain/comparison.ts` 对两个同一场景族的已确认版本分别运行验证，按固定用例 ID 对齐新增失败与恢复通过。对照版本控制差异方向，不改变任何产品预期；报告可导出两版场景及逐项证据。

## 交互与存储

场景库有十四个模板、八类触发信号与十二项模拟能力。新增场景会补入旧缓存，不覆盖已有自定义版本。场景版本按模板存于浏览器 `cabinlab.scenarios.v1`，每个模板最多 30 个版本。读取时重新校验，不把任意本地数据直接送进执行器。存储不可用时给出提示，当前会话仍可工作。

生成请求使用 AbortController 和递增请求 ID；取消、编辑、切换场景会使旧响应失效。运行时独立于 React 重渲染；切换场景会停止旧时钟并丢弃该台架状态。

运行轨迹不自动持久化。`src/domain/evidence.ts` 支持导入运行证据或完整实验：最多 1 MB、1 小时、1000 条输入和 4096 条事件；严格校验字段、运行时、命令和事件的顺序，在独立实例中重放，并比对事件、终态、时间、状态、进度、锁和在途请求。文件内验证报告不参与预期。导入不覆盖当前场景、版本或运行，也不访问外部服务。此检查验证内部一致性，不能证明来源或防止同时篡改输入与结果。

## 可配置模型的边界

适配器支持 Chat Completions 与 Anthropic Messages，不依赖厂商特有工具调用或 JSON Schema 输出参数。两种协议共享编译指令、场景校验、可配置超时（默认 30 秒，最多 120 秒）、有界响应读取和取消逻辑。Messages 使用顶层 system、输出上限和文本块响应；推理块不进入场景或前端结果，截断和工具调用会拒绝。服务必须返回原始 JSON 文本，Markdown 围栏或非法场景会显式失败。请求拒绝自动重定向，保护认证头。

服务默认绑定 `127.0.0.1`，API 检查同源 Origin，禁用缓存，限制请求体和同时编译数。它不是公网多用户服务；当前没有认证、按用户配额、分布式限流或可靠作业队列。

同一模型尝试的截止时间涵盖请求、响应流读取和一次定向修复。配置备用时，仅在鉴权、限流、连接、超时或服务不可用的错误后按顺序换模型。用户取消贯穿所有尝试。OpenAI 备用端点固定，使用独立密钥。对上游错误只返回受控消息。原生协议启用 SSE 并要求完整终态，原始事件流限 4 MB，普通 JSON 限 100 KB，最终文本限 30000 字符。模型协议和切换顺序均由受控响应测试验证。

依赖锁定在 `package-lock.json`。`esbuild` 和 `minimatch` 的 overrides 使用已修复版本，已通过类型检查、lint、构建及浏览器验证；升级上游依赖后可以重新评估是否删除 overrides。
